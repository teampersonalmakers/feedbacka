# 컨설팅 녹취 → 케이스 파일 → AI 등록

한 번의 요청으로 끝낸다. 입력은 녹취 텍스트 파일(자막 그대로, 화자 표시 없음) + 수강생 이름 + 회차 + 상담일. 출력은 아래 3개 + Firestore 등록.

## 0. 시작 전 확인

- 같은 수강생의 이전 회차 케이스 파일이 `cases/`에 있으면 **먼저 읽는다.** 이번 회차에서 무엇이 바뀌었는지 짚어야 한다.
- `docs/STANDARD-제2의커밍쏜-2026-09-22.md`(제2의 커밍쏜 기준서) 1절(커밍쏜 판단 7패턴), 2절(승인 기준)을 읽는다. 케이스 파일의 "코칭 케이스"는 이 패턴을 근거로 쓴다.
- 상담일이 없으면 사용자에게 묻는다. 추정하지 않는다.

## 0-1. 입력이 유튜브 링크일 때 — 대본 직접 추출

컨설팅 녹화가 유튜브(비공개·일부공개)에 올라가 있으면 링크만 받는다. 텍스트 파일을 따로 요구하지 않는다.

**1순위: Claude in Chrome (mcp__claude-in-chrome__*)** — 비공개 영상은 로그인이 필요해서 이 경로가 기본.
1. `tabs_context_mcp` → `tabs_create_mcp` → `navigate`로 링크 열기
2. 영상 아래 설명란 "...더보기" 클릭 → "스크립트 표시" 버튼 클릭 (없으면 영상 하단 "..." 메뉴 → "스크립트 표시")
3. 스크립트 패널 우측 상단 "⋮" → "타임스탬프 전환"으로 타임스탬프 끄기
4. `get_page_text` 또는 `read_page`로 스크립트 패널 텍스트 추출. 패널이 길면 스크롤하며 여러 번
5. `data/tr/{videoId}.txt`로 저장. 첫 줄에 영상 제목·URL
6. 탭 닫기

로그인 안 돼 있으면 사용자에게 "크롬에서 유튜브 로그인 후 다시" 요청. 스크립트 버튼이 없으면 자막이 아직 생성 안 된 것 — "업로드 후 자막 생성까지 보통 수 시간, 나중에 다시" 보고.

**2순위: yt-dlp** — 일부공개(unlisted)이고 Chrome이 안 될 때.
```bash
yt-dlp --write-auto-sub --sub-lang ko --skip-download --sub-format vtt -o "data/tr/%(id)s" "{URL}"
# vtt → 텍스트: 타임스탬프·중복 줄 제거
```
`scripts/`에 이미 자막 추출 스크립트가 있는지 먼저 확인(data/tr에 118편이 이 방식으로 들어가 있음). 있으면 그걸 쓴다.

추출한 텍스트는 이후 단계에서 녹취 파일과 똑같이 취급. 영상 제목에서 수강생 이름·회차를 읽되, 상담일은 영상 업로드일이 아니라 사용자 확인.

## 1. 녹취 읽기 규칙

자막은 화자 구분이 없고 오타가 많다. 이렇게 읽는다.

- **화자 판별**: 질문하고·정의하고·"타임"·"제발 그러지 마세요"·"어때요?" 하는 쪽이 커밍쏜. 자기 상황·사례·감정을 길게 말하는 쪽이 수강생. 확신이 안 서는 문장은 판단 카드에 쓰지 않는다.
- **오타**: 이름(수님·소님·손님 = 커밍쏜, 해리님·해림님 = 이혜림, 수현님 = 이수연 등)과 단어(코어 키워드 = 포어/쿠어/호워 키워드, 페르소나 = 페리소나/페려)는 문맥으로 복원한다. 복원이 안 되는 핵심 문장은 요약본에서 인용하지 않고 "○○로 추정되나 자막 불명확"으로 사용자에게 보고한다.
- **수치**: 수강생이 직접 말한 것만 쓴다. 커밍쏜이 예시로 든 숫자("월 1천 벌었다고 하면")는 수강생 사실이 아니다. 불명확하면 빈칸 대신 빼고 보고한다.
- **뺄 것**: 다른 수강생 실명이 들어간 이야기, 수강생 가족·건강·재정 세부, 컨설팅과 무관한 발언(정치·종교·검증 안 된 주장), 잡담·인사·장비 얘기.

## 2. 출력 ① 수강생 전달용 요약본

수강생에게 카톡·노션으로 보내는 글. 커밍쏜 톤(존댓말, 짧은 문장, 단정 먼저 설명 뒤, 이모지는 📌와 1️⃣2️⃣3️⃣만).

구조는 회차에 따라 다르다. 그 회차에서 실제로 다룬 항목만 쓴다. 다루지 않은 항목은 넣지 말고 "이번 회차에 없음"으로 보고한다.

```
**N차 컨설팅 요약**

**\* 주제 관련된 내용 :**          ← 1회차 또는 주제 재설정 시
**\* 결핍 (N-1회차에서 바뀐 것)**   ← 2회차 이후는 "무엇이 바뀌었나" 중심
**\* 극복 방법**
**\* 방향성**
**코어키워드 : ○○**  (변경됐으면 "A → B")
**메세지 : ○○**  (미완성이면 공식만)
**페르소나**
**브랜드 로드맵** (표: 주제 / 메시지 / HOW / WHO / 얻는 것 + 한 문장)
**\* 제안하는 라이프스타일**
**\* 콘텐츠 소재 리서치 피드백**
**\* 레퍼런스 채널**
**📌 ○요일까지 미션**
마무리 한 줄 (커밍쏜이 실제로 한 격려 문장)
```

규칙:
- 결핍·극복·방향성은 **수강생 1인칭**("저는 ~했어요"). 커밍쏜 코멘트는 그 아래 불릿으로 분리.
- 커밍쏜이 실제로 한 표현을 그대로 가져온다. 다듬지 않는다. ("더 버려야 돼요", "내가 보려고 콘텐츠 만드는 게 아니에요")
- 커밍쏜이 든 비유·본인 사례(퍼메스=비트코인, 캠핑 채널 멍타임, 디지털 노마드)는 넣는다. 이게 설득 구조다.
- 수강생이 저항하거나 헷갈린 지점과 커밍쏜이 어떻게 되돌렸는지를 남긴다.
- 미션은 요일·제출 방법까지.

## 3. 출력 ② 커밍쏜 AI용 케이스 파일

파일명: `cases/컨설팅_{이름}_{N}회차.md`. 실명은 파일명에만. 본문은 "피부 전문의 고객", "뷰티샵 원장 고객"으로.

```markdown
# [PT 컨설팅 케이스] {익명 유형} · {N}회차 · {이 회차 한 줄}

- 상담일: YYYY-MM-DD
- 고객 유형: (직업, 경력, 채널 상태)
- 컨설팅 단계: (이 회차에서 한 일 → 화살표로)
- 결과: (확정된 것 / 미션으로 이월된 것)
- WHY 디깅 경로: 경로 1(결핍 극복형) 또는 경로 2(고객 의미 발견형). 얼라인먼트 이슈 있었으면 유형 A/B. → 방법론 파일 참조
- 이전 회차에서 변경: (2회차 이후만) 결핍/코어 키워드/메시지/라이프스타일 중 바뀐 것과 이유
- 태그: #...

---

## 1. 컨설팅 요약본 (고객 전달 최종본)
(출력 ①을 3인칭·평서문으로. 1인칭 결핍·극복·방향성은 "(고객 1인칭)" 표시하고 그대로)

## 2. 코칭 케이스 (고민 → 커밍쏜 판단 → 근거)
### 케이스 A. "수강생이 한 말 그대로" 또는 상황 제목
- 상황: 
- 커밍쏜 판단: (단정)
- 근거: (원칙·비유·본인 사례. 기준서 1절 패턴 번호 붙이기)
- 대화 기술: (어떤 질문으로 끌어냈나, 저항에 어떻게 대응했나)
- 결과: (수강생이 어떻게 받았나)
(케이스는 5~12개. 잡담·장비·일정은 케이스가 아니다)

## 3. 이 컨설팅에서 드러난 커밍쏜 코칭 원칙
(번호 목록. 기준서 1절과 겹치면 그 번호 표시, 새 원칙이면 "신규")

## 4. 수강생 확정 로드맵 (있을 때만)
(수강생이 노션 워크시트에 확정한 WHY/HOW/WHO/WHAT, 페르소나, 내적·외적 키워드를 그대로. 
 채널 진단 기능이 로드맵 대조에 쓰는 데이터. 수강생이 쓴 것과 커밍쏜 조정본이 다르면 둘 다 표시)
```

노션 워크시트 링크를 받으면 **확정(확정) 표시된 항목만** 4절에 발췌한다. 여러 버전이 섞인 페이지를 통째로 넣지 않는다.

## 4. 출력 ③ 원문 메타 헤더

녹취 원문을 지식 소스로 넣기 전에 맨 위에 붙인다.

```
- 출처: 퍼메스 PT 1:1 컨설팅 {N}회차 녹취
- 수강생: {이름} ({익명 유형}) / 상담일: YYYY-MM-DD
- 이 회차 결론: (케이스 파일 헤더의 "결과" 한 줄)
- 화자 구분 없음. 커밍쏜 판단은 케이스 파일 컨설팅_{이름}_{N}회차.md 참조
```

## 5. 이전 회차 파일 갱신

2회차 이후, 이전 회차 파일에서 바뀐 항목 옆에 표시만 추가한다. 내용은 지우지 않는다.

```
**코어키워드 : 화합**  → *(2회차에서 '자신을 지키는 힘'으로 변경. 컨설팅_이수연_2회차.md 참조)*
```

방법론 파일(`방법론_WHY디깅_두가지경로.md`) 케이스 매핑 표에 이 회차 행 추가 또는 갱신.

## 6. 등록

```bash
# 케이스 파일 → 판단 카드(승인 상태) + 지식 소스
FIREBASE_SERVICE_ACCOUNT=... node scripts/import-case-doc.mjs cases/컨설팅_{이름}_{N}회차.md
# 이전 회차 갱신본: 기존 카드 덮어쓰지 말고, 변경 표시된 항목만 새 카드로
# 원문 (메타 헤더 붙인 것) → insight.html 지식 소스 추가 경로 또는 /api/kb-embed
```

import-case-doc.mjs 는 헤더의 `- 상담일: YYYY-MM-DD` 를 consultedAt 으로 읽는다(확인됨, 2026-09). 상담일 줄이 없으면 기수 어림값으로 떨어지니 반드시 넣는다. 같은 제목이면 같은 id 로 덮어쓴다(재등록 안전).

## 7. 보고

마지막에 사용자에게 4줄:
1. 만든 파일 목록
2. 이번 회차에서 바뀐 것 (이전 회차 대비)
3. 자막 불명확·미확인 수치 등 **확인 필요 항목**
4. 등록 결과 (카드 N장, 소스 N건, 임베딩 상태)

## 하지 않는 것

- 녹취에 없는 판단을 만들지 않는다. 커밍쏜이 명확히 말한 것만.
- 커밍쏜 표현을 "다듬지" 않는다. 오타 복원만.
- 수강생 말을 커밍쏜 판단으로 쓰지 않는다. 헷갈리면 뺀다.
- 회차에서 다루지 않은 항목을 형식 맞추려고 채우지 않는다.
- 실명을 본문에 쓰지 않는다.
